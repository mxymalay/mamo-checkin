# 可视化规则生成器设计

日期：2026-09-23

状态：用户已确认本文设计；实施计划已编写，尚未开始产品代码实现。

## 目标与成功条件

用户无需 AI Agent、API Key 或模型额度，即可在 Gmail、Moodle、Ed 的消息页面点选签到图片，生成当前 v1 格式的 JSON，在预览后保存为本地规则并选择启用。普通用户不需要理解 CSS、JSON 或规则 ID。

生成器解决“在消息里定位图片”，不改变 OCR、日期解析、账号验证、课程验证、签到资格或候选码提交策略。一次点选只能产生候选规则，不能证明未来页面都兼容。

成功条件：用户可在正常模式完成“选课程与来源 -> 点图片 -> 确认匹配结果 -> 保存并启用”；无需先导出再导入文件。预览阶段不提交签到、不写入正式收集记录、不消耗生产扫描缓存。

## 选定方案与范围

- 内置在签到助手，入口位于“识别与模块 / 规则库”，与“导入 JSON”并列，名称为“从页面创建”。弹窗提供当前页快捷入口；不增加独立扩展或新仓库。
- 编辑器作为模块页中的独立创建视图，保留主页面公共头部及未保存的设置草稿。完成或取消后返回原规则库分页。
- 新增代码按点选器、选择器生成、后台会话和编辑器 UI 分开；未来可拆分，但第一版不建设跨扩展通信。
- 保持规则 schemaVersion 1。输出仍是现有规则引擎可验证的数据，不包含脚本、步骤、坐标、任意请求地址或远程执行能力。
- 第一版支持已打开且可验证的消息/帖子内的 IMG；Ed 支持现有引擎已经认可的图片附件链接。不支持 PDF 内部、canvas、CSS 背景图、闭合 Shadow DOM、跨域 iframe 或全屏灯箱副本。
- 本次不修改版本号、不发布主扩展 Release、不自动上传 GitHub。

## 用户流程

### 1. 选择来源

从规则库进入时，选择已配置课程、已启用来源以及该来源的已打开标签页。列表仅列出受支持的网站，不展示无关浏览历史。弹窗快捷入口使用当前受支持标签页，再确认课程。

课程或来源尚未配置时，引导用户进入对应配置，不擅自新增或更改课程。没有适用标签页时显示“先打开包含图片的消息”，仅在用户明确点击后打开其已配置来源入口。

第一版不自动遍历邮箱、切换账号或跳转其他帖子。规则定位无法修复来源搜索阶段未找到消息的问题，遇到这种情况应返回对应的检索配置或诊断。

### 2. 点选目标

用户点击“开始点选”后，在选定标签页显示就地悬浮工具条和图片轮廓。支持点击图片、键盘在可选图片间移动、Enter 选择、Escape 取消；不点击网页原有链接，不拦截页面输入和登录。

只允许选择现有来源适配器认可的内容根节点内的图片。账号菜单、头像、广告、签名、引用内容、其他消息或不允许的域名均不能通过点选绕过正式过滤。

来源账号和课程不能确认时停止并解释原因。用户选中节点后再次核验该节点仍在原文档和原消息中；SPA 跳转、图片被替换、标签页关闭均使当前选择失效。

### 3. 生成与调整

自动推断来源，生成稳定的随机规则 ID，例如 local.generated.<随机标识>，初始版本为 1.0.0。这里的 local 只是命名，实际来源仍由库的 origin=local 管理。名称默认为课程与来源，用户可以修改；不自动使用邮件主题、发件人姓名或账号信息。

自动生成相对于消息根节点的选择器。用户可以添加正例图片或标记“这张不要”，系统重新计算能表达这些要求的规则。不能用当前 v1 格式表达的排除条件须明确报告，不得只在预览中偷偷过滤。

不要求用户编辑 JSON；普通模式显示规则名称、课程、来源、匹配数量及图片预览。开发者模式额外显示候选选择器、过滤原因、样本结果和 JSON 预览。

### 4. 验证与预览

调用生产使用的图片定位引擎，以“仅当前草稿规则”测试，不能让内置规则兜底掩盖草稿失效。默认展示本消息中所有命中的图片与数量，而不只展示用户刚刚点击的那一张。

标记三种结果：未匹配、需要调整、当前样本通过。通过至少要求目标图片被正式引擎接受、所有正例命中、所有排除样本未命中、没有截断结果，且用户确认命中集合正确。未标记的额外匹配需逐项确认或排除。

规则只剩通用 img 等宽泛条件，或只依赖可疑动态结构时，标记“范围较宽/稳定性待验证”，不提供直接启用；允许保存草稿、继续增加正反样本或手工导出后调整。单个样本永远不显示“永久有效”。

可选操作：用户打开同课程另一条消息并明确选择“添加验证样本”；最多验证 5 条消息、每条最多 20 个用户标记。历史样本仅检验定位，不改变生产流程的最近时间窗口或允许提交范围。

可选 OCR 测试：沿用现有浏览器 OCR / Apple Vision 选择及下载限制，只识别已验证命中的图片；不填写或提交签到。使用现有 preview-only 识别路径，不归档原图或写正式记录。识别正确不代表规则能适应未来页面。

### 5. 保存与启用

- “保存草稿”：仅加入“本地导入”，不绑定课程。
- “保存并启用”：在当前有效预览确认后，一次保存规则并更新明确选中的课程/来源绑定；保留原先其他规则与内置规则。
- “导出 JSON”：导出可由现有导入器接受的纯规则包，不含样本、正文、图片、OCR 输出、临时 URL、会话信息或 origin 字段。

默认只绑定创建时选择的课程。同一规则要共享给其他课程，必须用户额外选择，并核验各课程对应来源已启用；未验证课程显示“该课程尚未验证”，第一版不直接为这些课程启用，可稍后验证再启用。

沿用社区与本地合计最多 8 条绑定限制。同 ID 的社区包不可覆盖；重命名不改变 ID。对已有本地规则的更新沿用替换确认和回滚语义，保存前再次校验库修订，防止覆盖其他页面的并发修改。

启用仅改变后续检查使用的规则，不立即执行签到。启用确认处说明后续手动/定时检查会按现有设置运行；已有定时任务不被擅自开启或关闭。

## 生成算法与边界

1. 从已验证内容根节点到目标节点生成有限的相对路径候选，优先考虑可重复的标签、结构类与经过允许列表筛选的通用属性。
2. 不使用图片完整地址、带签名参数、邮件/帖子实例 ID、账号标识、正文文字、位置坐标、nth-child、随机 CSS 类或未知属性值。class/id 看似固定也不是稳定性的证明。
3. 通过现有 validateSelector 和 validateRule 检验候选，使用同一 root 和 runtime.locate 测量正例召回与误选；按覆盖样本、排除误选、选择器复杂度和稳定性启发式排序。
4. 不把整页唯一当作好规则：可接受一条规则选中同一消息中的多张已确认图片。只截取图中一个区域不在第一版范围内。
5. 生成的排除选择器必须符合当前 excludeSelectors 仅针对图片节点匹配的语义。若需要祖先排除而 v1 无法表达，拒绝该候选，不扩大语法。
6. 输出不自动填充 navigation/context 关键词；这些字段不能从单次点图可靠推出。第一版保留现有搜索/导航行为。
7. 每次生成限制 64 个候选、路径最多 6 层，遵守已有 8 选择器/64 KiB 包及引擎节点预算。超限明确失败，不默默显示部分成功。

## 架构与复用

现有接点：

- modules-host.js / modules-page.js / module-tabs.js：保留页头、草稿和返回状态的模块导航。
- source-rules/format.js：JSON 与选择器验证。
- source-rules/runtime.js：与生产一致的定位、引用/装饰图/域名过滤及结果预算。
- gmail.js / moodle.js / ed-adapter.js：身份、课程、消息根节点与来源证据。
- source-rules/library.js：本地/社区隔离、修订、绑定、回滚。
- background-rules.js / test-runner.js：忙碌协调、预览下载及 preview-only OCR。

新职责：

- picker：已打包的隔离世界内容脚本，只管理当前页点选覆盖层、节点引用与生命周期。
- selector-generator：纯生成与验证逻辑，以脱敏结构特征、正反例为输入，不持有 Chrome API 或持久化能力。
- builder-session：后台授权与会话控制，绑定发起 UI、目标 tab、frame、document、来源和课程；处理预览与过期。
- builder-ui：正常用户向导、结果预览、保存确认及开发者诊断。

适配器需要增加只读“获取可点选内容根节点”的能力，并与原生产读取共享同一套根节点/验证逻辑，避免再写一份宽松的页面定位代码。根节点句柄只保留在隔离世界，跨进程只传会话内不透明标识。

现有 ruleTest* 接口仅限开发者模式，不能为了普通用户生成器整体放开。新 builder* 接口只允许当前已授权点选会话中的草稿与图片，内部复用窄范围预览工具；既有完整测试台权限不变。

保存并启用需提供一个受互斥保护的库操作，先完整验证规则、来源、课程、绑定数量与预览草稿摘要，再合并读取的最新状态，在一次 storage.local.set 中写库与绑定。校验或存储失败时不得留下部分启用结果，不用先 import 后 bind 的两次调用模拟原子操作。

## 权限、安全与生命周期

现有 manifest 已有 scripting 与三个来源站点的 host_permissions。第一版只在这些既有授权站点工作，不新增所有网站权限，不自动增加 activeTab、debugger、外部扩展通信或远程脚本权限。具体页面权限被用户撤销时显示权限提示并停止。

内容脚本结果视作不可信输入。后台验证 sender.id、tab/frame/document 和绑定会话；网页 postMessage 不作为授权入口。保存只接受发起的扩展 UI 消息，点选页面不能直接保存或启用规则。

会话最多存活 10 分钟，同一时刻只允许一个生成会话。不以保持 service worker 常驻为前提：工作线程重启则会话失效，页面提示重新开始；已保存规则不受影响。

预览期间不与真实签到、身份检测或完整开发者规则测试并发，使用后台共享忙碌控制。生成会话不改变自动检查设置；退出或过期后释放忙碌状态，定时检查沿用原调度，不追加“补跑”。

Escape、取消、返回、关闭生成页面、目标标签页关闭、来源导航、权限变化或会话过期时清理高亮、事件监听器、观察器、预览资源和令牌。页面侧也有独立过期清理，不能只依赖后台清理通知。

生成阶段不上传数据。原始 DOM、样本图、来源 URL 和 OCR 结果只用于会话内预览，不写持久化存储、不进入诊断导出；保存的只有合法规则和显式绑定。共享社区仍通过用户主动导出与提交，不自动推送。

## UI、可访问性与国际化

用“选择图片 / 检查结果 / 保存”三个阶段呈现。结果预览占主要区域，JSON 不默认占屏。与现有模块页、图标和按钮风格一致，不新增营销页。

创建入口在正常模式可见；详细 JSON、选择器及过滤轨迹与开发者开关联动。普通用户仍能看到错误原因、图片结果和启用影响，不能把必要反馈藏在开发者模式。

新增全部文案使用现有翻译机制，提供 en、zh_CN、zh_TW 对应规则模块文案。覆盖长英文、390/768/1280 像素视口、键盘操作、焦点恢复、屏幕阅读器及减少动画偏好。覆盖层显示/隐藏就地完成，不从屏幕角落飞入。

## 验收与测试

1. 用各来源合成 DOM 测试根节点边界、相邻消息、错误课程、错误账号、引用/签名、头像、动态 class、懒加载、Ed 附件、非法 URL、节点替换和页面跳转。
2. 测试选择器符合现有 v1 语法；正反例可表达/不可表达时的输出；不能用 URL 或消息实例标识制造虚假唯一性；通用 img 不被标为可靠可启用规则。
3. 同一 fixture 的预览定位与生产定位结果一致；OCR 使用 preview-only 路径，正式记录、缓存及提交接口保持未调用。
4. 普通模式能完成向导，但不能调用已有开发者全量测试接口；伪造会话、错 tab/frame/document、过期令牌、网页消息和非法保存均被拒绝。
5. 保存草稿不启用；保存并启用保留其他绑定、内置规则与同 ID 社区版本；并发修订、超 8 条及存储失败无半完成状态。
6. 浏览器检查键盘点选、Esc、返回、语言切换、未保存设置草稿、长英文布局和移动宽度，不操作真实签到。真实账户页只有用户明确授权后做只读点选验证。
7. 全量回归与两种安装包校验通过后交付本地包，不自动发布 Release。
